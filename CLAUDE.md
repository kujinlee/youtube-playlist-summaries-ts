## Testing

Playwright e2e tests live in `tests/`. **Every new feature must have a corresponding test.**

- Tests run against the live dev server (`npm run dev` on `:3000`)
- Each test file is a standalone ESM script (`node tests/<name>.mjs`)
- Tests must clean up after themselves (restore any data they mutate)
- Use `DATA_ROOT` env var (defaults to `../youtube-playlist-summaries-data`) for data paths

Existing tests:

## Architecture

This is a Next.js 15 dashboard for browsing and managing a curated YouTube playlist of AI/Claude Code videos. **All data lives in the sibling `youtube-playlist-summaries-data/` folder, which is not tracked by git.**

### Data flow

```
page.tsx (server component)
  → reads manifest.json + archived.json from DATA_ROOT at request time
  → passes VideoWithMeta[] to Dashboard (client component)

Dashboard.tsx (client)
  → FilterBar: search/filter controls + Sync button
  → VideoTable: sortable/filterable video list
  → SyncLog: live SSE log panel shown during sync
```

### Sync pipeline (`/api/sync` → SSE stream)

`GET /api/sync` streams newline-delimited SSE log messages and terminates with `__done__`. The client (`Dashboard.tsx`) reconnects via `EventSource`, appends lines to `syncLines` state, and calls `window.location.reload()` on completion. The sync steps in `lib/sync.ts`:

1. `fetchPlaylist()` — spawns `yt-dlp` as a subprocess to get current playlist entries
2. `generateSummaryAndRatings()` — calls Gemini 2.5 Flash for each new video; returns markdown + JSON ratings block in a single response
3. Saves markdown to `SUMMARIES_DIR`, updates `manifest.json`
4. `syncArchiveFiles()` — moves/restores files between `video-summaries/` and `_archive/` based on `archived.json`
5. `removeFromPlaylist()` — removes newly archived videos from YouTube via OAuth (optional)

### Archive state

Archive is stored as `{ archived: number[], playlist_removed: string[] }` in `archived.json`. The `archived` field is an array of video **indices** (not IDs). `POST /api/archive` rewrites the entire `archived` array. `playlist_removed` tracks video IDs already removed from YouTube so they aren't removed again.

### Manifest schema

`manifest.json` (shared with the Python version) contains `{ playlist_url, videos: Video[] }`. Each `Video` has `index`, `id`, `title`, `channel`, `lang` (EN|KR), `type`, `audience`, and five rating fields (U/D/O/R/C, each 1–5).

Score formula (`lib/manifest.ts:calcScore`): `U×0.35 + C×0.20 + D×0.15 + O×0.15 + R×0.15`

### Key conventions

- **Filenames**: `{2-digit-index}_{url-safe-slug}.md` — generated by `makeFilename()` in `lib/gemini.ts`
- **Language detection**: Korean is detected by counting `[가-힣]` characters in the title; summaries are generated in the video's language
- **Token file**: `token-ts.json` lives in the project root (not the data folder), separate from the Python version's token
- **DATA_ROOT**: defaults to `../youtube-playlist-summaries-data` relative to `process.cwd()`; override via `.env.local`

## Environment variables

Copy `.env.local.example` to `.env.local`:

```
DATA_ROOT=/absolute/path/to/youtube-playlist-summaries-data
GEMINI_API_KEY=your_key_here
```

YouTube OAuth credentials (`client_secrets.json`) go in the data folder. On first sync a browser window opens for authorization; the resulting token is saved to `token-ts.json` in the project root.
